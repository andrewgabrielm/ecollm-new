# Engineering rules

Source of truth: `plan.md` (Plan v3.0; referenced as `PLAN.md` in instructions). Preserve existing work and source design documents. Follow its dependency order, stop at owner checkpoints, and record observed evidence in `BUILD_STATUS.md`. The current user task authorizes Step 09 only and supersedes the previous stopping point. Recheck previous functionality; implement owner-run hardware/catalog tooling, approved initial install verification, local runtime wiring and gated synthetic smoke/feasibility; stop before Step 10. Automatic verification stays offline/mocked: real hardware profiling, runtime calls, inference, downloads and experiments remain owner-run checkpoints.

## Mandatory environment rules

- Use Python 3.11.
- Always reuse the `.venv` virtual environment located in the project root. If absent, create that environment with `uv venv --python 3.11 .venv`; never replace an existing environment without checking it.
- Never create additional virtual environments or install dependencies globally.
- Use `uv` for dependency management.
- Maintain `pyproject.toml` and `uv.lock`; use locked dependency installation and document tool versions.
- All Python execution, testing and training must use the project virtual environment. Invoke `.venv/bin/python` and tools in `.venv/bin`, or explicitly direct `uv` to the root environment. Do not execute system Python, use temporary `uvx` environments, or implicitly download a Python runtime.

## Architecture and scope

- Build a single-user, local-first broker, with React on loopback and FastAPI, initially one process/worker. A profile ID is not authentication. Future APIs must reject hostile hosts/origins and require local write authorization for approvals, deletion, preferences and model operations.
- Preserve the sequence: validate → analyze/mask PII → trusted sanitized payload → features/immutable eligible-roster snapshot → routing → model-scoped exact/guarded semantic cache → policy gate immediately before generation → eligible local cascade → conditional authorized cloud → inspect/restore locally → eligible cache/allowlisted telemetry.
- The orchestrator is the sole generation dispatcher, including retries, synthetic warm-ups and evaluation. Neither routing, portfolio optimization nor provider internals may bypass the gate. Keep pure per-request ranking separate from infrequent model lifecycle operations. Separate generation/health/warm-up Provider interfaces from RuntimeControl list/pull/unload/remove.
- Use frozen validated sanitized payloads, immutable plans and roster snapshots, typed outcomes/errors and explicit schema/model/policy/artifact versions. Validate all request/config boundaries; Pydantic inputs forbid extras. Canonical hashes must be deterministic.
- Default to `local_only`, unspecified sensitivity and an 8,000-character prompt limit. Task categories: qa, summarise, extract, classify, reason, format, code. Cloud-preferred categories default empty; no hidden domain-quality claims.
- Budgets: local 60s, cloud 30s, overall compute 120s, approval 120s; separate human pause from bounded resume compute. At most one reauthorized local connection retry within deadline; no cloud retry. Health TTL 10s, invalidated on failure. Report explicit unavailable, timeout, policy-blocked, approval-conflict, disk and internal errors without content echo.
- Rule weights initially quality=1, latency=0.3, load=0.1 with fixed normalization reference; hypotheses require measurement. Rules remain the fallback on absent/incompatible/unvalidated learned artifacts.
- Keep SQLite state/artifacts under ignored local directories, apply versioned migrations, WAL and foreign keys, serialize bounded writes. Do not fabricate OpenAPI before routes exist. Never commit model weights or runtime state.
- No automatic learning/promotion, unattended swaps, agents, RAG, multi-user service, additional production runtime adapters or uninspected streaming within MVP scope.

## Privacy and authorization invariants

- Fail closed on scanner/sanitizer failure: zero generation calls. Only a successfully validated sanitizer output may become trusted input. Sanitizer implementation belongs to Step 03.
- RequestContext and placeholder maps stay request-local, in memory only, redacted from repr, exceptions and serialization. Never expose maps or credentials to the frontend. Approval state survives only until approval/expiry/cancellation, with explicit cleanup.
- Reserve/escape user-authored placeholders. Restore only valid current-request map tokens locally. Inspect outputs for new PII/unknown tokens; on inspection failure return a masked warning and do not cache. Never fetch analyzer/model assets in a request path.
- No raw prompts, outputs, PII, placeholder maps or credentials in logs, telemetry, training metadata, persistent profiles, error reports or exports. Later eligible caches are the narrow explicit opt-in exception for inspected non-sensitive local content; apply all cache guards. Use synthetic markers in tests.
- Cloud hard-blocks and allowed fallback reasons are checked before proposing approval. Bind exact sanitized preview/approval to request ID, digest, target, mode, policy and expiry; consume atomically once, reject replay/tampering/policy changes. Keys are environment-only; cloud destinations configured/validated. Benchmark authorization is separate from user-traffic consent.
- Exact cache, semantic cache, workload persistence, local learning and persistent analytics have independent opt-ins, off by default. Unspecified/confidential scope or detected PII bypasses caching/learning. Retention, TTL and entry bounds are configurable; deletion/opt-out invalidates affected state and derived live-trained artifacts, retaining synthetic baseline fallback.
- Cache lookup follows routing. Only successful, eligible, validated and inspected local answers may be cached, under the actual producing model/version (cascade B must never be stored as A). Include scope, prompt whitespace, task, parameters, mode/policy/config/template/context and provenance in compatibility. Never cache cloud or best-effort failure outputs; inspect hits; cache failure falls through.
- Semantic reuse stays default-off and limited to eligible FAQ-style cases; code, changing facts, numbers, negation and uncertain compatibility must miss. No cloud embedding provider.

## Model lifecycle and learning constraints

- Start with two verified local models, at most three managed installed SLMs; resident limits derive from actual hardware. Temporary staging requires explicit approved swap and disk headroom. Unknown resources/measurements remain unknown. No real install during Steps 01–02.
- Catalog real eligibility requires pinned source/digest/runtime identity, license review, platform/resource compatibility and verification. Unverified placeholders are never eligible in real mode. Never download arbitrary UI-provided tags/URLs or delete unrelated external runtime models.
- Downloads, destructive retirement and promotions require the applicable owner approval. Bind swap approval to manifest/version/digest/policy/deletion intent; use immutable snapshots, in-flight leases/drain, serialized durable operation state, atomic activation and rollback preserving a known-good local model.
- Benchmarks contain public/licensed or invented data only. Freeze source/template-family-disjoint train/validation/heldout splits and hashes; fitting/tuning cannot read heldout. Use identical feature extraction at fit/inference, only pre-generation features, never target leakage.
- Distinguish objective quality, format validity, latency and satisfaction. Thumbs-up is not a correctness label; missing labels stay null; no inferred counterfactual outcomes or fabricated live data. Report failures, counts, uncertainty, simulated results and missing runs honestly. Smoke subsets do not establish quality improvements.
- Load only verified known local native artifacts, never untrusted pickle. Train offline, validate with predeclared criteria, promote manually and preserve rollback. Unknown models/schema mismatch/corruption fall back to rules. Do not execute arbitrary generated code on the host; trusted benchmark code requires an isolated offline sandbox.

## Coding, command and testing standards

- Use typed, focused modules along the plan's package boundaries. Keep contracts explicit and immutable where shared; reject malformed/unknown inputs with safe errors. Do not log validation input values or claim scanner perfection/OS isolation.
- `make help` lists only implemented targets and prerequisites. Commands reject invalid inputs with nonzero exit, write artifacts only to ignored local paths, and give safe summaries and actual paths. No fake success for missing dependencies/data/models/credentials.
- `make lint test` always means fast offline Ruff, mypy and pytest checks, excluding marked slow tests. Never start runtimes, install assets, run inference or use real endpoints in tests/CI. Pin the lockfile and CI actions/tools; include secret scanning. `make test-privacy` exists from Step 01, with actual privacy-engine tests added Step 03 onward; disclose empty coverage.
- Step 01 gate: import smoke, safe config defaults/MOCK_MODE, slow-marker exclusion, no secrets in logs, `make help`, `make lint test` all observed passing.
- Step 02 gate: malformed requests/manifests rejected, consent off, deterministic hashes/versions, repr/serialization redaction, forward/reopen migrations with WAL/foreign keys/local paths, unverified real-mode exclusion, `make lint test` passing.
- Step 03 gate: masking/restoration, overlaps retaining every sensitive type, duplicate/forged/concurrent tokens, scanner/sanitizer fault injection, zero dispatch on untrusted input and safe logs/state; `make lint test test-privacy`. Real NLP smoke is explicitly slow and cannot be claimed when the asset is missing. No suffix-list/model downloads during analysis.
- Step 04 gate: mocked HTTP success, timeout/unavailable/401/429/malformed responses, zero hidden retries, strict destinations, credential-safe errors, deterministic mock behavior and disabled control mutations; `make lint test`. Unknown residency/pricing remains unavailable.
- Step 06 gate: hints/category order, structural validity distinct from correctness, deterministic two-of-three ranking, missing/unhealthy/unknown candidates, fixed normalization, shared feature schema, immutable snapshot/lease behavior and no router/provider imports; `make lint test`. Synthetic capability fixtures must remain labeled and excluded from real-mode priors. Runtime reconciliation only consumes read-only metadata; full lifecycle operations remain Step 17.
- Step 07 gate: mock local A/B and structural cascade, budgets, masking and zero-call privacy faults, exact one-time approval/decline/expiry/replay/policy-change handling, no-model/unauthorized-cloud cases, output inspection and cleanup failures, tight HTTP host/origin/write guards; `make lint test test-privacy smoke`. Export OpenAPI from actual routes.
- Step 08 gate: typed API/schema drift checks, local-only chat, exact preview and best-local-answer approval, decline/expiry/cancellation, error/loading/accessibility and no frontend credentials or stored chat content. Unit/RTL and Playwright smoke use mocks only. `make lint test test-ui smoke`; owner reviews the local visual demo.
- Step 09 gate: unknown/low-memory hardware fixtures, verified catalog/source/digest/platform/disk checks, explicit bound owner install authorization, post-install identity verification before eligibility, unknown metrics and guarded synthetic smoke/feasibility. `make lint test test-privacy`; no real calls by default. Collect the owner hardware/runtime report before selecting actual model tags or requesting downloads. Do not start Step 10.
- Later steps require privacy fault injection/zero-call assertions, policy matrix/replay/concurrency tests, cache provenance/deletion negatives, model-operation rollback, split/artifact integrity and appropriate UI/mock E2E checks. Release baseline broker/privacy coverage is ≥80%; do not game coverage or relax security to pass a milestone.
- Record actual commands, exit codes, test counts, manual requirements and unresolved issues in `BUILD_STATUS.md`. Never mark work complete solely because documentation or mocks exist; distinguish mock, synthetic, real and NOT_RUN evidence.
